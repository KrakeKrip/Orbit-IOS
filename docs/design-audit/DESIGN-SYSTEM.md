# Предлагаемая дизайн-система Orbit iOS

**Дизайнерское предложение D. Не описание текущей реализации.** Правила предназначены для существующих возможностей Orbit. Числа ниже — стартовая спецификация для проверки в SwiftUI, а не требование пиксельно повторить статические PNG.

## 1. Принцип иерархии

Экран отвечает на три вопроса в одном порядке: **где я → какую дату/область смотрю → что с задачами**. Для всех разделов общая оболочка: native tab bar, заголовок, меню существующих действий, контекст даты и вида, рабочая область, общий «+». Список, повестка, день и месяц отличаются рабочей областью. Для пользователя задача остаётся тем же объектом.

Акцент выделяет действие/выбор. Поверхность организует содержимое. Статус объясняется словами и символом, а не только цветом. Плотность уменьшается удалением вторичного содержимого, а не бесконечным уменьшением шрифта.

## 2. Типографика

SF, системные text styles, текущая локаль и Dynamic Type. Не фиксировать размер `system(size:)` для основного текста без масштабирования. Время — tabular/monospaced digits; названия задач и дат обычной пропорциональной ширины.

| Роль | Базовый размер при Large | Вес | Правило |
|---|---:|---|---|
| Заголовок раздела | 24 pt, масштабируемый относительно title2 | Bold | Один уровень во всех разделах, до 2 строк для длинного проекта |
| Заголовок редактора | 17 pt / headline | Semibold | Нативная inline navigation title |
| Название задачи в списке | 17 pt / body | Regular | Неограниченный перенос, не обрезать высоту строки |
| Компактная задача без времени | 15 pt / subheadline | Regular | 1–2 строки при обычном размере; при AX размерах растёт и переносится |
| Заголовок календарного блока дня | 13–15 pt, scalable | Medium | По доступной высоте; сначала название, затем время |
| Заголовок блока «3 дня» | 12–13 pt, scalable | Medium | Не уменьшать ниже 12 pt; при нехватке места дополнительная информация через существующее меню |
| Метаданные задачи | 13 pt / footnote | Regular | Один стиль для времени, проекта, срока, напоминания; до нескольких строк без scaleFactor |
| Заголовок секции | 15 pt / subheadline | Semibold | Одинаковый регистр и цвет, без декоративных uppercase |
| Шкала времени | 12 pt / caption | Regular | Моноширинные цифры; заметность ниже названия задачи, но достаточный контраст |
| Вторичная отметка / точки | 11–12 pt / caption2 | Medium | Не использовать для единственного названия задачи или важной ошибки |
| Действия | 17 pt / body | Regular / Semibold для подтверждения | Не уменьшать текст ради однострочного toolbar; адаптировать размещение |

**Dynamic Type:** отступы могут расти умеренно, текст — по системному стилю. Нельзя удерживать текст в фиксированном круге 32 pt, карточке 28 pt или шапке 64 pt. При AX размерах контекстная строка может стать двумя строками; выбранный день — форма с минимальным размером, а не `frame(width:height:)` поверх растущих цифр. Календарная временная геометрия не растёт вместе с font size, поэтому внутри короткого блока применяется сокращённое содержимое, а читаемый полный путь остаётся в существующих списке/повестке и меню.

## 3. Геометрия и плотность

| Token / элемент | Стартовое правило |
|---|---|
| Базовая сетка | 4 pt; основные интервалы 8, 12, 16, 24 |
| Внешнее поле содержимого | 16 pt, одинаковое по разделам |
| Внутренний gap строки | 12 pt между control и текстом |
| Gap title → metadata | 4 pt |
| Вертикальный inset строки | 10–12 pt; высота от содержимого |
| Список: минимум | 52–56 pt без метаданных; обычно 64–72 с одной строкой метаданных |
| Компактный untimed | min44 pt, содержимое растёт; не высота 26/28 pt |
| Область отдельной кнопки | Целевой минимум 44×44 pt; соседние области не перекрываются |
| Completion glyph | 22 pt; отдельный target 44×44, выровнен по первой строке |
| Иконка toolbar | 18–20 pt, одинаковый вес Medium; target44 |
| Иконка в строке / статусе | 14–16 pt для metadata, 18–20 для действий |
| FAB | 56 pt, плюс 24 pt; 16 pt от правой и нижней границы рабочей области над tab bar |
| Радиус пользовательского блока | Event/untimed 8–10 pt; preview 12 pt |
| Нативные поверхности | Sheet, menu, grouped Form, tab bar используют системную форму, не подгоняются под пользовательский радиус |
| Разделитель | 0.5–1 pt, от leading текста до внешнего trailing; в календаре нейтральная сетка 0.5–1 pt |
| Нижний inset scroll | По реальному overlap FAB; ориентир 56+16+12 = 84 pt **сверх** уже учтённой native safe area, без двойного добавления tab bar |

Нельзя компенсировать проблему высоты пяти минут увеличением рисуемого интервала до 44 pt. Геометрия времени и область взаимодействия проектируются раздельно. Расширенная цель короткого блока не должна перекрывать цель соседнего без правила однозначного выбора.

**Светлая:** canvas white, grouped surfaces через системные нейтральные цвета, остальные роли семантически те же. **Системная:** следует системному light/dark; app appearance не меняет размеры или структуру компонентов. Слоновая кость сохраняет светлую схему независимо от system dark — это явный выбор темы.

Это исходные пары для прототипа. До принятия измерить rendered colors, включая native glass/tint, Increase Contrast и доступность на устройстве. Сейчас кодовый коралл/white ≈3.57:1; предложенный `#B94236`/white ≈5.39:1, secondary/ivory ≈5.44:1. [Повторяемый расчёт](contrast-calculation.txt). Цель — ≥4.5:1 для обычного текста, ≥3:1 для большого и значимых нетекстовых индикаторов; разделитель сетки не должен конкурировать с задачами. Ориентиры: [W3C](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum), [Apple](https://developer.apple.com/design/human-interface-guidelines/accessibility).

Насыщенный коралл не заполняет каждую задачу по умолчанию. Кромка, выбранный элемент и главный action дают достаточно узнаваемости. Выделение, завершение и просрочка различаются не только оттенком: выбранный ряд имеет отдельный selection state; завершение — check/подпись; срок — flag и текст причины.

## 5. Общая оболочка и навигация

1. **Первый ряд:** название раздела, справа одно меню существующих действий. Предпочтительно native toolbar; не рисовать системное стекло вручную. Во вложенном проекте — native Back и название проекта.
2. **Контекстный ряд:** дата/период слева, текущий вид с текстом справа. Во Входящих и индексе проектов этот ряд отсутствует, потому что у них нет выбора вида/даты; высоту не резервировать пустым Spacer.
3. **Навигация по периоду:** одинаковые стрелки и target44. День листает день, повестка — неделю, 3 дня — три, месяц — месяц. Название/VoiceOver объясняет единицу шага.
4. **Возврат «Сегодня»:** одно место рядом с контекстом даты, если выбранный день/показанный период отдалён от сегодняшнего; появляется без скачка остальных контролов. В месяце важно учитывать и browsing month, и selectedDay.
5. **Пять пунктов меню вида:** существующие Список, Повестка, День (нынешний «Календарь»), 3 дня, Месяц. Переименование «Календарь» в «День» — рекомендация для ясности; смысл и набор видов не меняются. Today/project показывают только доступные им виды.
6. **Общий «+»:** один визуальный компонент. В Проектах создаёт проект, в папке — задачу проекта. Accessibility label всегда называет действие и контекст; для browsing month за пределами selectedDay дата назначения должна быть видна.

Текущие назначения формы сохранить: Входящие — без даты, Сегодня — реальный текущий день при открытии, Предстоящее — выбранный день, проектный список — без даты с project preset, проектный календарь — selectedDay с project preset. Вид и выбранная дата не должны сбрасываться побочным закрытием формы.

## 6. Задача как общий компонент

### Полная строка

Порядок: completion target → текстовый блок. Внутри блока:

1. Название 17 pt, с переносом, основной цвет.
2. Планирование: `09:00–10:30 · Работа` либо дата+время во Входящих. Проект показывается вне активной папки проекта. Внутри секции конкретного дня дата не повторяется. Для задачи без времени метка нужна только если без неё контекст неясен; не повторять «Без времени» у каждой строки одноимённой области.
3. Дедлайн с явным `Срок: 23 окт.`; при просрочке `Срок истёк: 21 окт.`. Напоминание `Напомнить: 18:00` или полная дата, когда отличается от контекста. При запрете — `Не доставится: уведомления выключены`. Не сокращать важную ошибку до цвета колокольчика.

При нехватке ширины metadata переносится по смысловым группам; порядок не меняется. Все значения доступны в существующем preview. Не добавлять новые теги, приоритеты и счётчики.

### Завершение и выбор

Completion — круг с check, selected bulk — отдельная заливка/selection state и фон строки; отличать их в VoiceOver. Визуальный круг может оставаться похожим на текущий, но выбранное состояние не должно восприниматься как уже сохранённое завершение. Завершённый текст читаемый и вторичный, без радикального уменьшения opacity. В bulk нажатие на всю строку выбирает её; индивидуальное complete/action menu временно отключены, как сейчас.

### Календарный блок

Точная формула высоты по времени сохраняется. Масштаб 64 pt/час — baseline текущего приложения, не менять одновременно с жестами. Три варианта содержимого для обычного текста:

| Реальная высота блока | Содержимое |
|---:|---|
| ≥48 pt | Название до 2 строк + время, если всё помещается |
| 24–47 pt | Одна строка названия; время только если реально помещается без уменьшения |
| <24 pt | Компактный маркер/название при возможности; полный диапазон через существующее меню/список |

Это правило рассчитывается по измеренному тексту, а не только по magic thresholds; Dynamic Type может перевести блок в более компактный вариант. Календарь не должен рисовать 2 строки в высоте, допускающей одну.

Пересечения — отдельные lanes с gap2–4, одинаковые surfaces, без случайного цветового кодирования. Выделение — явный outline/handles поверх блока, без смены точного интервала. Ошибка сохранения возвращает отображение persisted state и показывает сообщение. На переходе через полночь mark продолжения и полный исходный диапазон в меню: `22 окт. 23:45 — 23 окт. 00:15`.

Untimed day и 3-day используют одну семантику/палитру. Различие количества колонок не означает отдельный тип задачи. Ограничение просмотра 3 → раскрытие примерно до 7 → внутренний scroll остаётся существующей возможностью, но размер viewport должен рассчитываться от реальных строк, а не множителя 28. Счётчик «Ещё N» и раскрытие — одно понятное действие, hit44; arrows не отделять от подписи слишком далеко.

## 7. Формы и меню

Общий `EditorContainer`: NavigationStack, нативные Cancel/Save в toolbar, Form с темой, один локальный draft и один финальный save. Сохранение не выполняется при закрытии/свайпе. Ошибка не уничтожает draft. Длинные формы — large; medium допустим для действительно короткого поля только при видимых действиях и корректной клавиатуре.

| Форма | Единый вариант |
|---|---|
| Создать задачу | Multiline название, проект, дата, время, дополнительные поля; toolbar Cancel/Add |
| Переименовать задачу / проект | Тот же title input, toolbar Cancel/Save, min validation у поля |
| Изменить дату | Контекст задачи кратко, необязательная дата, picker, нейтральное «Без даты», toolbar |
| Время / длительность | Начало и длительность, раскрыта одна группа; вычисляемый конец, нейтральное «Без времени», toolbar |
| Проект задачи | Native inline selection, полное переносимое имя, toolbar Save |
| Дедлайн | Общая date row с объяснением независимого срока, toolbar Save |
| Напоминание | Включение, дата, время, состояние разрешения/очереди; toolbar Save |
| Массовый перенос | Количество, новая дата, предупреждение о сохранении времени/срока/напоминания; те же закреплённые действия |
| Настройки | Native Form, группы «Оформление / Уведомления / Отклик», native Done |
| Звук | Отдельные выбор и preview, обе цели ≥44, selected озвучивается; тишина не имеет фиктивного preview |

**Необязательные значения:** открытие picker не присваивает дату само. Если было nil, пользователь явно включает дату/срок, затем wheel меняет draft; сохранение записывает draft. Так устраняется нужда в дополнительной кнопке «Выбрать эту дату» для неподвижного wheel на today. Этот сценарий требует отдельной проверки, потому что текущая кнопка решает реальную проблему `onChange` при неизменённом значении.

**Клавиатура:** название растёт до нескольких строк; содержимое формы прокручивается над клавиатурой, toolbar остаётся. В multiline поле Return означает перенос; сохранение — явная кнопка. Если сохраняется keyboard-submit, подпись клавиши должна обозначать сохранение, а не двусмысленное «Готово». Это предложение требует согласованного изменения поведения на этапе реализации.

**Действия задачи:** tap открывает существующий popover; preview нейтральный, max2–3 строки + компактный контекст. Группировка: завершение; дата/время/проект/срок/напоминание; переименование/удаление. Меню ограничивается доступной высотой, прокручивается, закрывается снаружи. Все команды остаются доступны при крупном тексте. Удаление — единственная destructive сущность, с нативным подтверждением. Текущее безвозвратное удаление не превращается в корзину в этом проекте.

## 8. Взаимодействия и motion

| Ввод | Контракт |
|---|---|
| Tap по названию | Existing action popover; не смещать исходную строку/интервал |
| Tap по completion | Сохранить complete/reopen, один feedback после успешного save |
| Hold по списку | То же меню; не вводить неожиданный drag списка |
| Scroll с карты / пустой сетки | Scroll без записи и без входа в editing |
| Устойчивый hold календаря | Выделение + existing move; сохранить baseline `891ac15` (0.45 s native recognizer) |
| Повторный drag с выделенного блока | Должен по-прежнему позволять scroll до нового hold; не возвращать прежний direct move |
| Drag ручки | Изменить именно начало/конец, показать точное candidate time; target не ловит соседнюю задачу |
| Hold пустоты | Существующий create preview; запись только после Add, Cancel полностью снимает preview |
| AutoScroll | Только в активной move/resize/create; прекратить при отпускании/cancel, стабильное время без двойного учёта scroll offset |
| Bulk | Tap выбирает всю строку, tabs заменяются действиями, Cancel возвращает навигацию |

Сохранить шаги существующего ядра: move5, resize10, duration5, start input1 мин. Не унифицировать их без отдельного поведенческого задания. Автопрокрутка должна начинаться до попадания пальца в tab bar/FAB; конкретную зону и скорость настраивать на измеренных жестах после визуальных изменений.

Стартовые длительности: pressed feedback немедленно; completion/selection150 ms; popover150–180 ms; смена вида/секции200–250 ms максимум. Интерактивный drag — без implicit animation геометрии. При Reduce Motion — без scale/move, допускается короткое opacity либо мгновенная смена. Обязательны прерываемость и отсутствие блокировки следующего tap. Не добавлять анимацию ради демонстрации редизайна.

Feedback: один selection tick при реальном изменении шага, один success на успешное завершение, один сигнал начала удержания. Навигационный medium/rigid impact следует оценить на устройстве; желателен более спокойный единый отклик. Пользовательские отключения haptics/sound сохраняются. Звук не должен подменять визуальное подтверждение и не должен превращать успешно сохранённую задачу в ошибку, если проигрывание не удалось.

## 10. Границы и критерии принятия

Перед реализацией зафиксировать выбранные tokens и шапку на четырёх макетах. Затем проверить на своих fixtures: пусто, 1 задача, много строк, 500 Unicode scalars, все metadata, 5 минут, много пересечений, midnight interval, выбранные/завершённые, denied/error, keyboard, light/dark/system/ivory/OLED, Increase Contrast, Dynamic Type, Reduce Motion, VoiceOver. Прохождение части этой матрицы в текущем аудите не означает, что остальные клетки закрыты.

Отдельный acceptance criterion для жестов: любое улучшение hit areas/радиусов/отступов должно сохранить `891ac15` scroll и атомарное сохранение даты+интервала. Изменение layout способно поменять global frames и зоны recognizer даже без изменения самого gesture-кода.
