# Orbit iOS — правила работы

Этот репозиторий содержит только iOS-приложение и Swift-пакет OrbitCore с тестами. Веб-код перенесён в https://github.com/KrakeKrip/Orbit-Web. macOS-клиент вынесен и ожидает отдельного репозитория.

## Источники и процесс

Прямые инструкции пользователя имеют приоритет. PRODUCT.md описывает продукт, ARCHITECTURE.md — технические границы, DESIGN.md — интерфейс. README.md — обзор, TASKS.md — текущая очередь. Старые tasks/NATIVE-* и reports/NATIVE-* — исторические задания и свидетельства, а не актуальная очередь.

- Codex выполняет прямо порученные задачи самостоятельно; не делегировать без запроса пользователя.
- Один ограниченный результат — отдельная ветка и обычные коммиты. Перед изменениями проверять status, сохранять чужую работу; без reset, автоматического stash и переписывания истории.
- Подробные результаты и ограничения сохранять в reports/, сообщения в чате короткие.
- Не публиковать, не менять удалённые сервисы и не устанавливать на телефон без разрешения, данного в текущем контексте.
- Не коммитить секреты, личные данные, дампы и пользовательские базы.

## Проверки

DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer; глобальный xcode-select не менять. Core: swift test из apple/Orbit. iOS: схема OrbitIOS в apple/OrbitIOS/OrbitIOS.xcodeproj. Web/npm/Docker здесь не нужны.

Проверки соразмерны изменению: core/store — релевантные тесты и persistence; UI — сборка и свой Simulator с синтетическими данными. GUI управляется через CUA. Различать код, build, Simulator и физический iPhone. Не объявлять GUI/haptics/VoiceOver проверенными по одной сборке.

## Данные

Никаких тестов на личных stores. Не удалять контейнер или приложение ради обновления. Ошибка открытия базы не должна создавать пустую замену. SwiftData schema, UUID и существующие данные сохранять; миграции проверять на собственных старых fixtures.
